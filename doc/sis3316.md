# Struck SIS3316 digitizers

WebDAQ reads Struck SIS3316 boards (16 channels, 250 MHz 14-bit or 125 MHz
16-bit) over Ethernet next to the CAEN boards. One run can mix both: the CAEN
boards write `.caendat`, the SIS3316 boards write HDF5 files in the same run
directory, and the rates, spectra, alerts and auto-restart treat them alike.

The acquisition is done by `sis3316daq`, a pure-Python package from its own
repository, [SisDAQ](https://github.com/skowrons94/SisDAQ), pinned as a
submodule in `server/native/sis3316daq` and installed by `install.sh`. It can
also be used on its own, outside WebDAQ (see its README).

## Connecting the board

The SIS3316 needs a dedicated network link: a direct cable (or a switch) on a
second network interface of the DAQ PC, never the internet interface.

1. Give that interface a fixed address, without a gateway, e.g. with
   NetworkManager:

   ```bash
   sudo nmcli con add type ethernet ifname eno1 con-name sis3316 \
        ipv4.method manual ipv4.addresses 192.168.1.1/24 ipv4.never-default yes ipv6.method disabled
   ```

2. Map an IP address onto the board's MAC address, `00:00:56:31:6x:xx` where
   `xxx` is the board's serial number in hex (serial 108 → `00:00:56:31:60:6c`):

   ```bash
   sudo ip neigh replace 192.168.1.100 lladdr 00:00:56:31:60:6c dev eno1 nud permanent
   ```

   This entry does not survive a reboot. A NetworkManager dispatcher script
   that runs the same command when the interface comes up makes it permanent
   (on the LUNA DAQ PC: `/etc/NetworkManager/dispatcher.d/90-sis3316-arp`).

The board answers on UDP port `0xE000`. With VME FPGA firmware before
V3316-2008 it always answers *to* port `0xE000` on the PC, so only one program
on the PC can talk to it: stop other SIS3316 tools while WebDAQ runs.

## Adding it

On the **Boards** page, *Add a Struck SIS3316*: enter a board ID (unique among
all boards) and the IP address, then *Check connection* — it shows the serial
number, firmware and temperature of the board that answered — and *Add
SIS3316*. The board's settings file `conf/SIS3316_<id>.json` is created with
defaults (all channels off) and a calibration file `calib/SIS3316_<id>.cal`.

## Settings (DAQ page)

Selecting an SIS3316 on the DAQ page shows its own dashboard instead of the
CAEN register view. Channels are numbered 0 to 15, as on the CAEN boards and
the histogram pages (Struck's manual calls them Ch1 to Ch16).

**Settings** works like the CAEN page: **Channel enable** switches channels on
(nothing is recorded until one is on; *All on* / *All off* for the whole
board), and **Channel settings** lists every setting for the *Default* column
and each enabled channel. The Default column applies to all channels not
changed themselves; a value changed for one channel is highlighted, and the
arrow in its header puts it back on the defaults. **Acquisition** below holds
the board-wide settings (sample clock, readout interval, event window,
pre-trigger, waveform and trapezoid trace lengths, pileup windows, NIM input TI).

| Setting | Meaning |
|---|---|
| On | The channel triggers and records events |
| Polarity | Negative inverts the input (the board triggers on rising edges) |
| Range, 50 Ω, Offset | Input range (5 V / 2 V / 1.9 V), termination, offset DAC (32768 = centred) |
| Threshold | Trigger threshold in ADC counts of pulse height |
| Trig P / G, CFD | Fast trapezoid (trigger) peaking and gap times, constant-fraction timing |
| E P / G | Energy trapezoid peaking and flat-top times |
| τ table / τ factor | Decay correction of the energy filter (0 = off). Table 0 at 250 MHz: τ ≈ 2097 µs / factor |
| Divider | Spectrum bin = max energy / divider. With divider = energy peaking, the bin is the pulse height in ADC counts |

Saved settings apply at the next run start. During a run they reach the board
at the next bank swap, except the clock and the waveform and trapezoid trace
lengths, which shape the run file and are refused until the run stops.

The *waveforms* switch of the histogram pages turns the raw samples of an
SIS3316 on (1000 samples, or the last length used) and off.

## The board's own utilities

* **On-board histograms** — the board histograms the energy of every hit
  itself (64K bins, with the channel's divider), independently of the
  software spectra. Read any number of bins, clear one channel or all;
  WebDAQ clears them at every run start.
* **Counters** — the trigger statistic counters since the run start: all
  internal triggers, recorded hits, triggers lost to dead time, pileup,
  vetoed and high-energy-suppressed triggers. During a run they also feed the
  rates: *Lost* is the dead-time counter, and *Triggers* (on the histogram
  cards, and `triggerRate` in Graphite) the internal trigger counter.
* **Filter trace** — the last recorded output of the energy (or trigger)
  trapezoid, for tuning peaking, gap and decay correction: with the right τ
  the flat top is flat. Needs a trapezoid trace length > 0.
* **Board info** — serial number, firmware, MAC address, sample clock and
  temperature (Struck recommends 50 °C or less).

## Run files

Each run writes `data/run<N>/run_<N>_<cycle>.h5`, next to the settings file
copied at the run start. The Data page lists them with the `.caendat` files.
They need no conversion:

```python
import h5py, numpy as np, json

with h5py.File("data/run12/run_12_0000.h5") as f:
    b = f["board_3"]
    ev = b["events"][:]                  # one row per hit
    ch14 = ev[ev["channel"] == 14]       # channels are numbered 0-15, as everywhere in WebDAQ
    energy = ch14["energy_max"] / 200    # / divider -> pulse height in ADC counts
    t_ns = ch14["timestamp"] * b.attrs["ns_per_sample"]
    settings = json.loads(b.attrs["settings"])
    waves = b["waveforms"][:10]          # row-aligned with events, if recorded
```

Rows are written bank by bank and channel by channel, so sort by `timestamp`
when the order matters (coincidences).

## Test mode

With `TEST_FLAG=True` an SIS3316 is simulated: every enabled channel sees a
pulser of fixed amplitude, so adding the board, settings, runs, spectra and
files all work without hardware.
